# 日本語の文章設計

文章もコンポーネントの動作の一部です。非エンジニアが対象と操作を理解できることを標準にします。

## 見出し

ページ見出しは対象を示す名詞を基本にします。「タイポグラフィ」「カラー」「通知設定」など、ナビゲーションと同じ語を使います。説明文で目的と条件を補います。抽象的な決意、過剰な読点、画面と関係のない比喩を見出しにしません。

| 変更前 | 標準 | 理由 |
| --- | --- | --- |
| 読むための、文字。 | タイポグラフィ | ページの対象がわかる |
| 自分に合う、心地よさ。 | 通知設定 | 変更できる内容を明示する |
| 判断には、根拠を。 | Knowledge | ナビゲーションと一致する |
| 送信できません | メールアドレスの形式を確認してください | 修正対象を示す |

## 操作ラベルとフィードバック

- ボタンは動詞を含める。「保存する」「設定を保存」「一覧に戻る」。単独の「OK」「こちら」は避ける。
- エラーは対象・原因・回復方法を示す。技術的な原因が未判明なら推測を書かない。
- 成功表示は実際の作用範囲に合わせる。ローカルデモなら実サービスへの保存や送信を主張しない。
- 空状態は何がないか、次にできる操作を示す。利用者を責めない。
- 機能説明は一文一義。本文はです・ます調。用語は同じ意味で統一する。

## 組版

本文16px・行間1.7を初期値とし、長文の行長は概ね日本語30〜45字を出発点に実画面で調整。本文は通常の字間を保つ。`palt`や追い込みは見出し等で効果を確認した場合だけ採用する。禁則、英数字、括弧、長いURL、200%拡大を確認。欧文ディスプレイ用の負の字間は日本語本文に継承しない。

## レビュー

見出しだけを読んで目的地を選べるか。操作前に結果を予測できるか。エラーを読んで自力で修正できるか。読み上げでも意味が通るか。これを満たさない場合、表現の個性より明確さを優先します。
