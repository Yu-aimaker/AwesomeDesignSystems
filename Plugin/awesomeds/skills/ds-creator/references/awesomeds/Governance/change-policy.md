# 調査と標準の更新

## 責務

Referenceは出典URLと確認状況。Knowledgeは確認事実・推論・適用案。AwesomeDSは採用済みのルール。Pluginは適用手順と正本の配布。サイトはそのルールを体験する実装です。

## 変更の手順

1. 一次資料の本文と該当実装を確認し、確認日・範囲・取得不能を記録する。
2. どのユーザー課題が改善するかを述べる。見た目の流行だけでは変更しない。
3. 既存標準と対立する点を比較する。違う組織の規則を同時に強制しない。
4. 代表画面に適用し、変更前後を同条件で評価する。
5. 正本を変更し、サイトとPluginを生成する。移行方法を記録する。
6. 採用・保留・却下を記録し、確認していない資料を採用理由にしない。

## バージョン

追加のテーマ・ガイドはminor。既存トークン削除や意味変更はmajor。記述修正や互換性のある不具合修正はpatch。v1.1は新しい領域と用途別テーマの追加で、旧トークンを維持します。

## 毎週の更新

同梱の週次GitHub Actionsはソース取得と内容の変更検出を行います。意味のある設計変更はこの採用手順でレビューしてから反映します。ワークフローをリポジトリにPushし、ActionsとPR作成権限を有効にするまで定期実行は始まりません。
