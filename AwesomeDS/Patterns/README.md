# 画面パターン

コンポーネント単体では利用体験を保証できません。対象、操作、結果、回復までを一つのパターンとして設計します。

| パターン | 必要な状態 | 操作と回復 | サイトの実例 |
| --- | --- | --- | --- |
| タスク一覧 | 未完了・完了・全完了 | チェックを戻せる。進捗が一致する | Overview / 業務ツール |
| 選択と学習 | 未回答・不正解・正解 | 理由をその場で表示、再回答可 | Overview / 学習アプリ |
| 製品・作品の比較 | 現在位置・次の対象 | 一回の操作で一対象、ループ位置表示 | Overview / ブランドサイト |
| フォーム | 初期・入力・不正・成功 | 送信後に対象と修正方法、値保持 | Components / Text field |
| 設定 | 現在値・変更・保存済み | 保存後も再編集、保存作用の範囲を表示 | Components / Preferences |
| 検索 | 入力前・結果・ゼロ件 | カテゴリ切替、検索解除、一覧復帰 | Knowledge |
| 確認ダイアログ | 開・閉・確定・キャンセル | Esc、フォーカス復帰、破壊操作は明示 | Components / Dialog |
| AI会話 | 空・送信中・生成中・中断・完了・失敗 | 停止、再試行、入力保持、出典 | Knowledge / AI状態設計 |

AI会話は設計ガイドであり、このサイトに実際のモデル接続はありません。

## フォームの初期状態

入力が未完了という理由だけで送信ボタンを無効にしない。押した際に修正方法を示す。処理中の二重送信防止は別の理由として扱い、処理状態を表示する。フォームの不正判定は色だけに依存せず、入力とメッセージを関連付ける。重要なエラーはフォーカス移動またはライブ領域で認識可能にする。

参考: [Sparkleの送信ボタン](https://sparkle-design.goodpatch.com/guidelines/patterns/submit-button-initial-state)、[assistant-ui Elements](https://www.assistant-ui.com/elements)。前者は入力の不備を解消できる設計、後者は状態別に体験を試す情報構造を検討するために参照。
