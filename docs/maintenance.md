# 毎週のナレッジ更新

`.github/workflows/weekly-review.yml` は毎週月曜 09:00 JST（00:00 UTC）と手動起動に対応します。GitHub の都合で時刻は遅延する場合があります。既定ブランチへ配置し、GitHub Actions と「GitHub Actions による Pull Request の作成」がリポジトリ設定で許可されている必要があります。プライベートリポジトリでは Actions の利用枠が適用されます。

処理は一次情報を GET で取得し、ステータス、サイズ、タイトル、SHA-256 を記録します。1 件 15 秒、本文 2 MB で制限し、初回・変更・変更なし・失敗を分けます。JS 描画が必要なページは HTML シェルのみとなりうるため、成功でも内容を読めた保証にはしません。HTML のハッシュ変更も意味のある仕様変更を保証しません。

実行ごとに独立したブランチと draft PR を作り、レポートとベースラインをレビューできます。前回の PR をマージすることで次回の比較対象が進みます。未マージの場合は既定ブランチの最後に採用したベースラインと比較します。知識の意味的な要約・採否は人またはレビュー担当エージェントが確認して記録し、デザイン変更は自動でマージしません。

手動実行: `node scripts/weekly-review.mjs`。ネットワークが必要です。全部失敗した場合も証跡を保存し、終了コード 1 を返します。Actions の PR 作成が権限で失敗した場合も生成物は artifact とブランチに残ります。

新しい資料の発見は、定点監視だけでは完結しません。毎週の PR レビューで対象分野の一次情報を追加調査し、Knowledge と Reference へ採否を記録してください。監視対象を追加する場合は `scripts/weekly-review.mjs` の明示リストを編集します。現在は LLM API キー不要の定点監視とレビュー運用であり、自律的な発見・意味理解を行う常駐エージェントではありません。
